# Раздел «Алгоритмы» — загрузка JS-шаблонов

«Алгоритмы» — это место, где живёт логика интеграции с WMS. Восемь вкладок — по одной на каждый тип JS-шаблона. Изменения применяются мгновенно, перезагрузка устройства не нужна.

## Как открыть

Личный кабинет устройства (`http://[IP]/`) → раздел «Алгоритмы».

## Вкладки шаблонов

| Вкладка | Что туда писать |
|---|---|
| `jsScriptAuthMode` | Логика авторизации сотрудника по ШК / RFID |
| `jsScriptItemType` | Доп. экраны до измерения (тип упаковки, количество и т.п.) |
| `jsScriptHttpHandler` | HTTP-обработчик для вызова из других шаблонов |
| `jsScriptHistorySensor` | Структурирование данных истории |
| `jsScriptFinishSend` | **Главное — отправка результатов в WMS** |
| `jsScriptAction` | Действия и кнопки |
| `InfoscanPage` | Конфигурация главного экрана |
| `ScriptScheduler` | Шаблоны, запускаемые по расписанию |

В типичной интеграции достаточно настроить только `jsScriptFinishSend`. Остальное — опции.

## Редактирование

На каждой вкладке — текстовое поле с JS-кодом. Подсветки синтаксиса нет. Пишите код в нормальном редакторе (VS Code, Sublime, что угодно), потом копируйте сюда.

### Лучший workflow

1. **Соберите шаблон в [конструкторе](/integration/builder)** на сайте базы знаний. На выходе — готовый JS-код.
2. **Проверьте в [эмуляторе](/emulator)** — увидите, что бы отправилось в WMS на типичных значениях SENSOR.
3. **Скопируйте в редактор** (VS Code), доработайте под свою специфику.
4. **Вставьте в «Алгоритмы»**, нажмите «Сохранить».
5. **Сделайте контрольный замер** на реальном объекте — посмотрите на баннер и в WMS, что данные дошли.

## Сохранение

Кнопка «Сохранить» внизу страницы. Применяется мгновенно — следующее измерение уже пойдёт по новому шаблону.

Внутренних версий шаблонов нет — старый код просто перетирается. **Делайте резервные копии** перед существенными изменениями: скопируйте текущий код в файл `jsScriptFinishSend_v3_2026-05-15.js` где-то у себя.

## Отладка

Если шаблон не работает или работает не так — посмотрите в журнал устройства. У версии PRO есть встроенный просмотр логов:

Личный кабинет → системные логи → фильтр по «JS» или «Algorithm».

Внутри шаблона можно использовать `console.log(...)` — записи пойдут в этот журнал.

```javascript
resp: function (resp, httpCode) {
  console.log('HTTP code:', httpCode)
  console.log('Body:', resp)
  // ...
}
```

## Откат

Если только что сохранённый шаблон сломал измерения:

1. Очистите поле полностью.
2. Вставьте пустой `return {}` или прошлую версию из бэкапа.
3. «Сохранить».

Устройство при пустом `jsScriptFinishSend` ничего не отправляет, но измерения продолжают работать, просто остаются в локальной истории.

## Ограничения

- **Размер шаблона**: до ~50 КБ кода. Большие — разбивайте через `GLOBAL_VAR.store` или `jsScriptHttpHandler`.
- **Скорость**: шаблон должен отработать за разумное время. Сетевые запросы внутри `body` или `resp` — нормально, но не ставьте `while (true)`.
- **Песочница**: внутри шаблона **нет** Node.js API (`fs`, `path`, `process`). Только JS-стандарт + `SENSOR`, `BARCODE`, `HELPER_JS`, `GLOBAL_VAR` и обвязка транспортов.

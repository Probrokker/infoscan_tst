В каждом JS-шаблоне Инфоскана доступен набор глобальных переменных и хелперов. Они одинаковые во всех 8 типах шаблонов (`jsScriptFinishSend`, `jsScriptItemType`, и т.д.).

## SENSOR — данные с датчиков

Объект с текущими значениями измерения. Все поля становятся актуальными к моменту вызова `jsScriptFinishSend`. В `jsScriptItemType` (до измерения) значения ещё пустые.

### Размеры

| Поле                  | Тип    | Описание                                                  |
| --------------------- | ------ | --------------------------------------------------------- |
| `SENSOR.width`        | number | Ширина (мм по умолчанию, единицы зависят от DistanceType) |
| `SENSOR.widthFormat`  | string | То же, но отформатированное в строку                      |
| `SENSOR.widthUnit`    | string | Единица измерения (`'мм'`, `'см'`, `'м'`)                 |
| `SENSOR.height`       | number | Высота                                                    |
| `SENSOR.heightFormat` | string | Высота отформатированная                                  |
| `SENSOR.heightUnit`   | string | Единица                                                   |
| `SENSOR.length`       | number | Длина — **только для 3D 60 / 3D 90**                      |
| `SENSOR.lengthFormat` | string | То же отформатированное                                   |
| `SENSOR.lengthUnit`   | string | Единица                                                   |
| `SENSOR.depthFormat`  | string | Длина — **только для Camera**                             |

<Callout kind="warning" title="lengthFormat ≠ depthFormat">
Это **самая частая ошибка интегратора**. Для 3D 60 / 3D 90 используется `SENSOR.lengthFormat`, для Camera — `SENSOR.depthFormat`. Универсальный код:

```javascript
var len = SENSOR.lengthFormat || SENSOR.depthFormat
```

</Callout>

### Масса и объём

| Поле                  | Тип     | Описание                         |
| --------------------- | ------- | -------------------------------- |
| `SENSOR.weight`       | number  | Масса (кг по умолчанию)          |
| `SENSOR.weightFormat` | string  | Масса отформатированная          |
| `SENSOR.weightUnit`   | string  | Единица (`'кг'`, `'г'`)          |
| `SENSOR.volumeFormat` | string  | Объём отформатированный          |
| `SENSOR.volumeUnit`   | string  | Единица (`'м³'`, `'см³'`, `'л'`) |
| `SENSOR.ready`        | boolean | Флаг готовности данных           |

Единицы настраиваются в Личном кабинете устройства → «Настройки» → DistanceType / WeightType / VolumeType.

## BARCODE и ADDITIONAL_BARCODES

```javascript
BARCODE // string: последний считанный ШК
ADDITIONAL_BARCODES // string[]: массив доп. ШК из Item Type
```

Если `BARCODE` пустой при вызове Finish Send — оператор измерил объект, не сканировав ШК. Обработать можно так:

```javascript
if (!BARCODE) {
  throw Error('Не отсканирован штрих-код')
}
```

## DEV_CODE — код устройства

Уникальный идентификатор конкретного физического устройства. Удобен для маршрутизации в WMS (например, разные склады отправляют в разные эндпоинты).

```javascript
DEV_CODE // string: 'INF-3D90-00042'
```

## UNIQUE_INDEX_HISTORY

Уникальный индекс текущего измерения в локальной истории устройства. Растёт монотонно, обнуляется только при сбросе настроек. Полезен для дедупликации на стороне WMS.

```javascript
UNIQUE_INDEX_HISTORY // number: 142857
```

## HELPER_JS — встроенные утилиты

### toBase64

Кодирует строку в Base64. Главное применение — Basic-авторизация.

```javascript
'Authorization': 'Basic ' + HELPER_JS.toBase64('login:password')
```

### xmlToJson

Парсит XML/SOAP-ответ в JSON-строку. Дальше — `JSON.parse`.

```javascript
resp: function (resp, httpCode) {
  var json = JSON.parse(HELPER_JS.xmlToJson(resp))
  if (json.Envelope.Body.Status !== 'OK') {
    throw Error('Сервис вернул не OK')
  }
}
```

### xmlXPath

XPath по XML-документу. Возвращает строку.

```javascript
var code = HELPER_JS.xmlXPath(resp, '/Detail/code/text()')
if (code !== '0') {
  throw Error('Код ошибки: ' + code)
}
```

## GLOBAL_VAR — хранилище

Два уровня хранения: оперативная память (`store*`) и диск (`storeScheduler*`). Память чистится при перезагрузке устройства, диск — нет.

```javascript
GLOBAL_VAR.storePut('lastSession', BARCODE)
var prev = GLOBAL_VAR.storeGet('lastSession')

GLOBAL_VAR.storeSchedulerPut('referenceData', json) // переживёт перезагрузку
var ref = GLOBAL_VAR.storeSchedulerGet('referenceData')
```

Также есть `storeRemove`, `storeClearAll`, `storeSchedulerPush` (для очередей).

### Когда пригождается

- **Кеш ответов** из ConfirmBarcodePage, чтобы не дёргать WMS по одному и тому же ШК.
- **Очередь отложенной отправки**, если связь нестабильная: `storeSchedulerPush('queue', body)`, потом ScriptScheduler-шаблон по расписанию отправляет накопившееся.
- **Контекст пользователя** после авторизации: имя сотрудника, его роль.

## args — динамические результаты Item Type

В `jsScriptFinishSend` (и других «после» шаблонах) доступны результаты Item Type-экранов. Имена ключей задаются в шаблоне Item Type через поле `nameResult`.

Пример: если в Item Type был экран `ListButtonRowPage` с `nameResult: 'resultPackType'`:

```javascript
// В jsScriptItemType
return [
  function () {
    return {
      page: 'ListButtonRowPage',
      pageTitle: 'Тип упаковки',
      nameResult: 'resultPackType',
      pageButtons: ['Штука', 'Коробка', 'Паллета'],
    }
  },
]

// В jsScriptFinishSend
var packType = ITEM_TYPE.resultPackType // 'Коробка'
```

Точное имя контейнера — `ITEM_TYPE` в `jsScriptFinishSend`, `args` в `jsScriptItemType` (там это аргумент функции).

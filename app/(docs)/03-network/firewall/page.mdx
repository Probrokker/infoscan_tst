# VLAN, firewall, порты

Инфоскан сам по себе минималистичен по сети: ему нужно достучаться до вашего WMS и принимать входящие подключения от админа.

## Минимальные правила

### Исходящий трафик от устройства

| Направление | Протокол | Порт | Назначение |
|---|---|---|---|
| Устройство → WMS | TCP | 80 (HTTP) | jsScriptFinishSend `http` транспорт |
| Устройство → WMS | TCP | 443 (HTTPS) | jsScriptFinishSend `http` транспорт по TLS |
| Устройство → WMS | TCP | 21 (FTP) | `ftp` транспорт |
| Устройство → WMS | TCP | 990 (FTPS) | `ftps` транспорт |
| Устройство → WMS | TCP | 22 (SSH/SFTP) | `sftp` транспорт |
| Устройство → WMS | TCP | произвольный | `tcp` транспорт (укажите в шаблоне) |
| Устройство → OAuth-провайдер | TCP | 443 | `httpOauth` (если используется) |
| Устройство → NTP | UDP | 123 | Синхронизация времени |
| Устройство → DNS | UDP | 53 | Разрешение имён |

### Входящий трафик к устройству

| Направление | Протокол | Порт | Назначение |
|---|---|---|---|
| ПК администратора → устройство | TCP | 80 | Личный кабинет устройства |
| Внешний скрипт → устройство | TCP | 80 | `POST /api/gateway` (для режима «начало измерения по API») |

## Что не нужно открывать

- **Outbound к интернету в целом**: не нужно, кроме конкретных адресов WMS и OAuth-провайдера. Если ваша security-политика жёсткая — добавьте allowlist именно этих хостов.
- **Inbound от всего интернета**: вообще не должно быть. Устройство не должно светить в публичную сеть.

## VLAN

Стандартная практика — отдельный **VLAN для измерительного оборудования**:

- Все Инфосканы в этом VLAN.
- Доступ только до сетей: WMS-сервер, ПК администратора, NTP, DNS.
- Запрет на доступ к гостевой Wi-Fi сети, серверам с PII, и т.п.
- Запрет инициации соединений в VLAN снаружи (только админ из доверенной подсети).

Пример правил на L3-коммутаторе (псевдокод):

```
vlan 200 = "infoscan"
  acl-out: permit tcp from any to 10.10.5.10/32 eq 80      ! WMS HTTP
  acl-out: permit tcp from any to 10.10.5.10/32 eq 443     ! WMS HTTPS
  acl-out: permit udp from any to 10.0.0.1/32 eq 123       ! NTP
  acl-out: permit udp from any to 10.0.0.2/32 eq 53        ! DNS
  acl-out: deny ip from any to any                          ! всё остальное запрещено

  acl-in: permit tcp from 10.20.0.0/24 to any eq 80         ! admin к ЛК устройства
  acl-in: deny ip from any to any
```

## Wi-Fi отдельным SSID

Если используете Wi-Fi (только PRO) — выделите Инфоскану **отдельный SSID** с PSK, привязанный к VLAN измерительного оборудования. Никаких гостевых сетей, корпоративных сетей сотрудников и т.п.

Это критично, потому что Wi-Fi легко проинспектировать. WPA2-PSK с длинным паролем — минимум. WPA3 — лучше, если все ваши устройства его поддерживают.

## Сертификаты и TLS

- Если WMS работает по HTTPS — нужно, чтобы устройство **доверяло сертификату**. Самоподписанные сертификаты по умолчанию не проходят.
- Корпоративный CA: загрузка корневых сертификатов в trust store устройства — через поддержку «Инфотех». В стандартной поставке этой опции нет.
- Для тестов — можно поднять промежуточный HTTPS-прокси (nginx, Caddy), который терминирует TLS на доверенной стороне.

## mTLS

Не поддерживается напрямую в шаблоне. Если WMS требует двусторонний TLS — поднимите перед ним прокси, который терминирует mTLS с клиентским сертификатом.

## Проверка доступности

После настройки правил — проверьте с самого устройства (если у вас открыт SSH в версии PRO):

```sh
ping wms.example.ru
curl -v https://wms.example.ru/api/measurements
```

Или просто сохраните шаблон и сделайте контрольное измерение — если в баннере «Записано», значит сеть работает.

`ScriptScheduler` — единственный шаблон, который **не привязан к измерениям**. Срабатывает по расписанию, в фоне. Идеально для обновления справочников, синхронизации с WMS, отправки отложенной очереди.

## Типичные сценарии

- **Догонка очереди отправки** — если связь с WMS была нестабильной, FinishSend складывал измерения в `GLOBAL_VAR.storeSchedulerPush('queue', ...)`. ScriptScheduler по расписанию проходит по очереди и пытается дослать.
- **Обновление справочника номенклатуры** — раз в час подтягиваем актуальный каталог товаров, чтобы ConfirmBarcodePage отвечал мгновенно из локального кеша.
- **Отчёт за смену** — раз в сутки в 23:59 формируем сводку и отправляем в WMS / на e-mail.
- **Health check** — раз в 5 минут пингуем WMS и логируем доступность.

## Структура

Шаблон возвращает массив задач. Каждая задача — объект с расписанием и функцией.

```javascript
return [
  {
    name: 'sync-catalog',
    cron: '0 */1 * * *',                        // каждый час
    run: function () {
      // тело задачи
    }
  },
  {
    name: 'flush-queue',
    cron: '*/5 * * * *',                        // каждые 5 минут
    run: function () {
      // тело задачи
    }
  }
]
```

Формат cron — стандартный 5-полевой (минуты часы день_месяца месяц день_недели).

## Пример: отложенная очередь FinishSend

В `jsScriptFinishSend` при ошибке HTTP 5xx складываем в очередь:

```javascript
// jsScriptFinishSend
resp: function (resp, httpCode) {
  if (httpCode >= 500) {
    var queue = GLOBAL_VAR.storeSchedulerGet('pendingQueue') || []
    queue.push({
      barcode: BARCODE,
      width: SENSOR.widthFormat,
      weight: SENSOR.weightFormat,
      timestamp: Date.now()
    })
    GLOBAL_VAR.storeSchedulerPut('pendingQueue', queue)
    return {
      banner: 'Записано локально — отправим, когда связь восстановится',
      bannerColor: '#F59E0B',
      comment: 'В очереди: ' + queue.length
    }
  }
  // обычная успешная обработка...
}
```

В `ScriptScheduler` по расписанию читаем очередь и отправляем:

```javascript
return [
  {
    name: 'flush-pending-queue',
    cron: '*/5 * * * *',
    run: function () {
      var queue = GLOBAL_VAR.storeSchedulerGet('pendingQueue') || []
      if (queue.length === 0) return

      console.log('Scheduler: пытаюсь отправить', queue.length, 'записей')

      var failedRetries = []
      for (var i = 0; i < queue.length; i++) {
        var item = queue[i]
        try {
          // Здесь делаем HTTP-запрос. Так как мы вне обработчика SENSOR,
          // используем HELPER_JS.httpPost или HTTP_HANDLER.
          var result = HTTP_HANDLER.sendMeasurement(item)
          if (result.ok !== true) {
            failedRetries.push(item)
          }
        } catch (e) {
          failedRetries.push(item)
        }
      }

      GLOBAL_VAR.storeSchedulerPut('pendingQueue', failedRetries)
      console.log('Scheduler: осталось в очереди', failedRetries.length)
    }
  }
]
```

## Пример: ночная синхронизация каталога

```javascript
return [
  {
    name: 'sync-catalog',
    cron: '0 2 * * *',                          // каждый день в 02:00
    run: function () {
      console.log('Catalog sync: запуск')

      try {
        var catalog = HTTP_HANDLER.fetchCatalog()
        if (catalog && catalog.items) {
          GLOBAL_VAR.storeSchedulerPut('catalog', catalog.items)
          GLOBAL_VAR.storeSchedulerPut('catalogUpdatedAt', new Date().toISOString())
          console.log('Catalog sync: получено', catalog.items.length, 'товаров')
        }
      } catch (e) {
        console.log('Catalog sync: ошибка', e.message)
      }
    }
  }
]
```

В `ConfirmBarcodePage` уже не делаем HTTP — берём из локального кеша:

```javascript
// jsScriptItemType / ConfirmBarcodePage
{
  page: 'ConfirmBarcodePage',
  pageTitle: 'Подтвердите товар:',
  nameResult: 'resultConfirm',
  mainMessage: (function () {
    var catalog = GLOBAL_VAR.storeSchedulerGet('catalog') || []
    var item = catalog.find ? catalog.find(function (x) { return x.barcode === BARCODE }) : null
    return item ? item.name : 'Товар не найден'
  })()
}
```

## storeScheduler vs store

- `GLOBAL_VAR.store*` — хранилище **в оперативной памяти**. Чистится при перезагрузке устройства.
- `GLOBAL_VAR.storeScheduler*` — хранилище **на диске**. Переживает перезагрузку.

Для ScriptScheduler чаще нужен disk-store: данные должны быть доступны и после перезапуска устройства, иначе при сбое потеряем очередь.

## Где редактировать

Личный кабинет устройства → «Алгоритмы» → вкладка `ScriptScheduler`.

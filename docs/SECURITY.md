# Политика безопасности

## Раскрытие уязвимостей

Если вы обнаружили уязвимость в коде или в инфраструктуре проекта — пожалуйста, **не создавайте публичный GitHub issue**.

Напишите напрямую:

- **E-mail**: [sales@inf-tec.ru](mailto:sales@inf-tec.ru) (с темой «Security»)
- **Telegram**: [@kazartsevk](https://t.me/kazartsevk)

Мы ответим в течение 2 рабочих дней и согласуем процесс раскрытия.

## Что считается уязвимостью

- XSS, CSRF, инъекции в любой части интерфейса.
- Возможность исполнения произвольного кода из пользовательского ввода вне песочницы эмулятора.
- Утечка переменных окружения, токенов, секретов в собранный бандл.
- Обход CSP, HSTS, других защитных заголовков.
- Уязвимости в зависимостях с CVSS >= 7.0.

## Что НЕ считается уязвимостью

- Возможность исполнить произвольный JS внутри iframe-песочницы эмулятора — это by design, песочница изолирована.
- Возможность загрузить произвольный шаблон в Личный кабинет устройства — это by design, у admin есть полный доступ к настройкам.
- Информация в публичных PDF-инструкциях и в исходниках на GitHub.

## Поддерживаемые версии

Только `main` ветка. Релизные теги и LTS-версии пока не выделяем.

## Раскрытие зависимостей

`pnpm audit --audit-level=high` запускается на каждом PR. Обновления зависимостей — через Dependabot.

`gitleaks` сканирует историю на наличие случайно закоммиченных секретов — на каждом PR.
